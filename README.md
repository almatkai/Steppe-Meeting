# Steppe Meeting — Настольное приложение для протоколирования совещаний

Автономное настольное приложение на базе **Tauri 2 + React + TypeScript + Tailwind CSS** и локального бэкенда на **FastAPI**, ориентированное на корпоративное и государственное делопроизводство Республики Казахстан.

---

## Ключевые возможности

1. **Создание совещания из разных источников**:
   - Запись с микрофона в реальном времени с поддержкой паузы и индикацией уровня звука
   - Загрузка аудиофайлов (MP3, WAV, M4A, OGG, FLAC) с поддержкой Drag-and-Drop
   - Прямая вставка текста (стенограммы / расшифровки)
2. **Параметры совещания**:
   - Название, дата, выбор языка (KZ / RU / EN / Смешанный)
   - Повестка дня (Күн тәртібі)
   - Список участников с должностями
3. **Генерация официального протокола**:
   - Двуязычный протокол по стандартам делопроизводства (Хаттама / Протокол)
   - Разделение по темам, принятые решения, ответственные лица и сроки
   - Плавающий AI-тулбар: выделите любой фрагмент текста в протоколе, чтобы переписать или улучшить стиль с помощью локальной модели
4. **Краткое содержание (Executive Summary)**:
   - Главные выводы встречи
   - Матрица поручений (Поручение, Ответственный, Срок)
5. **Интерактивный AI Ассистент**:
   - Потоковый чат с ответами по стенограмме и протоколу
   - Быстрые шаблоны: составление драфта письма, список задач, выделение спорных вопросов
6. **Экспорт**:
   - Скачивание официального документа **DOCX** (русский / казахский)
   - Копирование текста протокола и резюме
7. **История и поиск**:
   - Полный локальный архив совещаний с мгновенным поиском по названию и тексту
8. **Компактный HUD виджет (Steppe Mini)**:
   - Плавающее окно поверх всех окон (320px в ожидании, 395px во время записи; 36px / 76px с субтитрами)
   - Выбор локальной STT модели прямо в Mini-панели (только среди фактически скачанных моделей)
   - Автоматическое отключение субтитров для тяжёлых моделей (>200 МБ) со снижением нагрузки на CPU/GPU и полным авто-анализом протокола после завершения
   - Опция ручного отключения стриминговых субтитров (кнопка CC) для экономии ресурсов
   - Stealth-режим: скрытие окна от демонстраций экрана и записи (⌘⇧M для скрытия/возврата)

## Быстрый запуск

### 1. Запуск приложения в один клик:
```bash
cd "steppe-desktop"
./run_app.sh
```

Скрипт автоматически:
- Проверит и поднимет виртуальное окружение Python (`backend/.venv`)
- Установит недостающие зависимости
- Скомпилирует и запустит Tauri десктоп-клиент
- Приложение само запустит бэкенд на `http://127.0.0.1:8008` и дождётся готовности, включая прямой запуск `.app` из Finder

Для запуска из исходников нужен `uv` (в PATH, `~/.local/bin` или Homebrew). Beta-дистрибутив **0.2.0-beta.1** для Apple Silicon / macOS 15+ включает CPython 3.12, `uv` и закреплённые core-зависимости. Установка Python, Node или `uv` пользователем не требуется. При первом запуске встроенный Python извлекается в `~/Library/Application Support/Steppe Meeting/runtime/<идентификатор сборки>/`, там создаётся окружение; базовый backend не требует сети. Release всегда использует backend из `.app`, даже при наличии checkout. Веса и среды STT устанавливаются отдельно по кнопке и требуют сети. Сборка, проверки, ограничения подписи и передача другим людям описаны в [DISTRIBUTION.md](DISTRIBUTION.md).

Backend принадлежит приложению и останавливается через Quit / ⌘Q. Закрытие главного окна сохраняет Mini и запись. Совместимый сервер этой же копии приложения и версии переиспользуется и не завершается приложением; другая копия или устаревший сервер на порту 8008 показывается как ошибка с предложением повторить подключение. Лог запуска: `~/Library/Logs/app.steppe.meeting/backend.log`. Скрипт больше не запускает Vite; для браузерной разработки используйте `pnpm dev`.

### 2. Ручной запуск (для разработки):

**Терминал 1 (Бэкенд):**
```bash
cd "steppe-desktop/backend"
source .venv/bin/activate
uvicorn desktop_server:app --host 127.0.0.1 --port 8008 --reload
```

**Терминал 2 (Фронтенд и Tauri):**
```bash
cd "steppe-desktop"
pnpm install
pnpm tauri dev
```

## Архитектура системы

- **Фронтенд**: React 19, TypeScript, Tailwind CSS, Phosphor Icons, Sonner (уведомления), Zustand (хранилище состояния).
- **Десктоп-оболочка**: Tauri v2 (Rust) с приватным API macOS для эффектов прозрачности/вибранси и нативным окном виджета Mini Mode HUD.
- **Бэкенд**: FastAPI, SQLite (`meetings.db`), локальная генерация документов `python-docx`.
- **Локальный AI (STT & LLM)**:
  - Интеграция с Ollama (по умолчанию `llama3:8b` или `qwen2.5:7b` для работы с казахским и русским языками)
  - Локальный STT движок Faster-Whisper и поддержка других локальных моделей для транскрибации речи без отправки данных в облако

## Настройка локальных моделей (Ollama)

1. Установите [Ollama](https://ollama.com/)
2. Загрузите рекомендуемые модели:
```bash
ollama pull qwen2.5:7b
ollama pull llama3.2:3b
```
3. Откройте **Настройки AI** в приложении:
   - Выберите провайдер **Ollama (Локально)**
   - Выберите загруженную модель из выпадающего списка
   - Нажмите *«Сохранить настройки»*.

В Mini кнопка «Стоп» завершает запись и создаёт протокол. «Сброс» возвращает начальное состояние, «Заново» сразу начинает новую запись; аудио и уже распознанные фрагменты предыдущей записи остаются черновиком в истории без запуска генерации. Субтитры находятся в отдельной панели на три строки с прокруткой. Во время потоковой записи CC управляет только её видимостью и не запускает повторное распознавание при остановке. Если CC выключен до начала записи либо выбрана модель >200 МБ, используется распознавание полного аудио после остановки. Крестик справа скрывает Mini целиком, сохраняя запись и распознавание; ⌘⇧M возвращает то же окно с текущим состоянием. Клик по иконке приложения в macOS Dock проверяет видимость Mini: если Mini скрыто, автоматически открывается и активируется главное окно Steppe Meeting; если Mini уже отображается на экране, фокус возвращается в Mini. Глазик переключает защиту всего Mini от захвата, сохраняя окно видимым и запись активной. На macOS защита применяется на главном потоке с проверкой состояния окна в оконном сервере; системные всплывающие подсказки подавляются, доступные названия кнопок сохраняются.

Проверка защиты: откройте Mini с включённым глазиком и запустите `xcrun swift scripts/check-mini-capture.swift --pid <PID приложения>`. Скрипт сравнивает пиксели всего окна в обычном захвате ScreenCaptureKit и при явном исключении приложения; изображения остаются в памяти. Для контрольной проверки выключите защиту глазиком и добавьте `--visible`: окно должно появиться в захвате. Это проверка конкретного API захвата, а не всех сторонних программ. После изменения фронтенда или Rust создайте новую сборку по [инструкции дистрибуции](DISTRIBUTION.md); изменения Vite сами по себе не обновляют `/Applications/Steppe Meeting.app`.

Проверка локального STT без скачивания весов:

```bash
backend/.venv/bin/python -m unittest discover -s backend/tests -v
node --experimental-strip-types --test tests/*.test.mjs
backend/.venv/bin/python -m unittest discover -s tests -p "test_*.py" -v
pnpm build
# macOS, после сборки .app; порт 8008 должен быть свободен:
backend/.venv/bin/python scripts/smoke-desktop-startup.py
```

Проверка скачанной модели на собственном аудио с заблокированным сетевым доступом во время инференса:

```bash
backend/.venv/bin/python backend/tests/smoke_local_stt.py \
  --model wav2vec2-rukk --audio sample.wav --language multi --expect қазақстан
# Для проверки полного скачивания и установки добавьте --download.
```

## Генерация через CLI

В настройках LLM выберите **API (HTTP)** или **Локальный CLI**. Поддерживаются OpenCode, Codex CLI, Claude Code и Antigravity (`agy`); приложение использует их существующий вход в терминале. Отдельные API-ключи для CLI не нужны. Пустой путь означает поиск в PATH, `~/.local/bin`, `~/.opencode/bin` и стандартных папках Homebrew. Ручной путь должен быть абсолютным и указывать на исполняемый файл.

«Проверить CLI» получает версию и доступный статус входа без запроса модели. Неизвестный статус входа не означает готовность (у Antigravity нет отдельной поддерживаемой команды проверки входа). «Тестовый запрос» отправляет ровно один короткий запрос на текущих, ещё не сохранённых значениях; он может тарифицироваться. Настройки сохраняются автоматически. HTTP-поля и путь/модель каждого CLI сохраняются при переключении режимов и провайдеров.

После успешного запроса заголовок, список CLI и sidebar показывают «Модель отвечает» для проверенных пути и модели. Неизвестный статус входа остаётся справочной информацией и не требует повторного входа. Результат хранится только в памяти процесса: смена пути или модели требует новой проверки доступа, а новая ошибка отменяет предыдущий успех. Сам запрос генерации также обновляет это состояние; проверки версии и входа не расходуют токены.

OpenCode требует явно выбранную модель `провайдер/модель`, с необязательным `#variant`. Список загружается командой `opencode models`; стоимость берётся только из метаданных его CLI API `/api/model`. Фильтр «Только бесплатные» доступен при наличии цен: нулевая стоимость должна быть явно указана для входа и выхода во всех ценовых уровнях. Название модели не доказывает бесплатность, лимиты бесплатного сервиса сохраняются. Без цен можно выбрать любую найденную модель или ввести ID вручную; отсутствующая в новом списке сохранённая модель не заменяется. Локальные провайдеры, например Ollama, настраиваются в самом OpenCode и тоже попадают в его каталог. У Codex и Claude модель вводится вручную; пустое поле использует настройки CLI. Antigravity поддерживает загрузку списка моделей.

Запросы OpenCode проходят через внутренний локальный proxy `backend/engine/opencode_proxy.py`: общий путь для теста подключения, генерации документов, шаблонов, чата и редактирования. Proxy запускает собственный `opencode serve` на временном loopback-порту с одноразовым паролем, создаёт сессию штатным локальным API и передаёт сериализованную историю ролей в `session.prompt`. Идентификатор сессии выделяет OpenCode; точная модель и `#variant` задаются при создании. Авторизацией и облачным запросом владеет установленный CLI.

При сравнении с рабочим T3-сеансом 2026-10-27 выявлена несовместимость ручных идентификаторов сессий в проверенном OpenCode 2.1.4: на одном собственном сервере, с одинаковыми моделью, запросом и policy, вручную заданный UUID дал HTTP 429, а выделенный сервером ID — `OK`. Прокси использует второй вариант. Полный тест через Steppe API с изолированной БД на `opencode/deepseek-v4.1-flash-free` завершился успешно. Исправленный proxy также проверен коротким ответом `OK` на установленном CLI 2.2.0. Это проверка конкретной версии и модели, а не гарантия доступности всех бесплатных моделей: действуют [условия OpenCode free tier](https://opencode.ai/v2/docs/console/api/inference).

При завершении, отмене и таймауте прокси прерывает и удаляет только свою сессию, затем останавливает собственный CLI-сервер. Существующие серверы и сессии T3/OpenCode не используются и не изменяются. Ответы и время выполнения ограничены; скрытого повтора, смены модели или прямого обращения к облачному API нет.

Локальный CLI может отправлять текст встречи в облако. Для полностью локальной генерации используйте локальную модель через API Ollama либо локального провайдера OpenCode. Ошибка CLI останавливает генерацию: приложение не переключает провайдера, API или модель. Ответ CLI сначала буферизуется, затем передаётся в существующий SSE чат; частичный неуспешный ответ не сохраняется как готовый.

Запуски используют временный рабочий каталог и ограничения инструментов; Codex, Claude и Antigravity получают длинные промпты через stdin: Codex — read-only sandbox, отключённые shell/MCP/hooks; Claude — пустой набор tools/MCP, safe mode и отключённые hooks; Antigravity — отдельный агент без tools в plan/sandbox режиме. OpenCode proxy использует штатный агент по умолчанию и native tool plugins, без custom system prompt. Временная [policy](https://opencode.ai/v2/docs/policies) `tool.use: * → deny` запрещает выполнение инструментов после agent permissions и сохранённых разрешений; permissions остаются `ask`, автоматического одобрения нет. Сторонние plugins, настроенный MCP, warming, LSP и formatter отключены в папке запроса; конфигурация провайдеров и вход остаются у CLI. На собственной временной сессии после загрузки native harness проверены ответы `deny` для shell, edit, read, execute и subagent через permission API; реальные команды/запись файлов не запускались. Собственная сессия запроса прерывается и удаляется при завершении, таймауте и отмене; существующие пользовательские сессии не затрагиваются. CLI без нужных flags/config возможностей требует совместимую установленную версию; ошибка не ослабляет ограничения.

Справка: [Codex exec](https://learn.chatgpt.com/docs/non-interactive-mode), [Claude headless](https://code.claude.com/docs/en/headless), [Antigravity headless](https://antigravity.google/docs/cli/headless/), [OpenCode CLI v2](https://opencode.ai/v2/docs/cli), [конфигурация OpenCode v2](https://opencode.ai/v2/docs/config).

## Монохромная иконка

Канонический источник Dock-иконки — `src-tauri/icons/icon-source.svg`: прозрачный холст 1024×1024, знак на сетке 824 px с отступом 100 px. Веб-источник — `public/steppe-icon.svg`, геометрия waveform/horizon общая с логотипом в sidebar. Все цвета нейтральные, без градиентов.

```bash
node scripts/generate-icons.mjs
pnpm exec tauri build --debug --bundles app
```

Скрипт использует встроенный SVG renderer **resvg** команды Tauri для `icon-1024.png`, затем `tauri icon` для PNG/ICNS/ICO и отдельно web PNG. Дополнительные iOS/Android/Appx ресурсы удаляются. Собранное приложение: `src-tauri/target/debug/bundle/macos/Steppe Meeting.app`. Для обновления Dock запустите заново именно эту сборку; установленная копия в `/Applications` не изменяется.

### Автосохранение и проверка обновлений

Настройки AI сохраняются автоматически: выбор — сразу, текст — после 500 мс без ввода или при выходе из поля. Состояние записи и ошибки видны в каждой секции; ошибку можно повторить. Неполные LLM-поля остаются в черновике и не блокируют сохранение STT. Очередь продолжает работать при переходе на другой экран.

Карточка «Обновления» отслеживает публичные GitHub Releases `almatkai/Steppe-Meeting`. Стабильный канал исключает предварительные сборки; бета включает оба вида. Канал сохраняется отдельно от AI-настроек. Проверки идут при запуске основного окна, каждые 6 часов и по кнопке; скачивания и установки нет. При отсутствии релизов приложение сообщает именно об этом. Ссылка на релиз открывается только по нажатию пользователя.

В нативной сборке версия берётся из Tauri `getVersion`, платформа и архитектура исполняемого файла — из `TAURI_ENV_PLATFORM` / `TAURI_ENV_ARCH`, переданных hook-командой Tauri в Vite. Собирайте frontend для приложения через `pnpm tauri build`, чтобы эти значения соответствовали целевой сборке. В браузере используется версия `package.json`; архитектура не угадывается по user-agent.

### Остановка генерации

Во время формирования протокола нажмите **Остановить** в карточке встречи. Приложение отменит запрос модели и дождётся очистки своего CLI-процесса или OpenCode-сессии. Аудио, стенограмма и предыдущий комплект результатов сохранятся. Для повторного запуска нажмите **Сформировать протокол заново**. Новые протокол, резюме, переводы и значения шаблона сохраняются вместе после успешного завершения; остановка или ошибка не смешивает их с предыдущей версией.

Остановка действует на генерацию этой встречи через API, OpenCode, Codex, Claude и Antigravity. Распознавание речи и запись используют свои элементы управления.
